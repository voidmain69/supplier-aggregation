# ADR-0009: Search-service — лексичний + семантичний пошук над індексом продуктів

**Статус:** прийнято · 2026-07-12

## Контекст

Люди й агенти шукають товари двома способами: точно (артикул/код/GTIN, ключові слова) і абстрактно
(«материнка під Ryzen 9000 з Wi-Fi 7»). RAG-інфраструктура (pgvector, `Embedder`) уже відпрацьована в
`matching`, але матчинг вирішує іншу задачу (зведення в канонічні). Пошук — окремий шов (репліки,
навантаження на читання), тож окремий сервіс (§5.7).

## Рішення

Новий `search-service` (через `make scaffold`), який **індексує з наявної події** `supplier.product.discovered`
(перший зріз — товари постачальників; канонічні через `catalog.product.updated` — наступний крок):

- **Лексика**: `search_text` — lowercased токенізований bag (name/brand/articul/codes); запит токенізується
  так само, **усі токени мають збігтись** (AND). Реалізовано через portable `LIKE`, тож юніт-тести йдуть на
  SQLite; на Postgres — `pg_trgm` GIN-індекс для швидкості. Точні lookup-и (code/articul/GTIN) — рівність,
  GTIN нормалізується до GTIN-14 (hard rule 5).
- **Семантика**: ембединг `brand + name` per товар; NL-запит ембедиться й матчиться cosine-nearest
  (pgvector `<=>` на Postgres, Python-cosine на SQLite). `Embedder`-протокол — шов; дефолт `HashingEmbedder`
  детермінований і безрозмірнозалежний, реальна модель підключається без зміни схеми (той самий підхід до
  ембедера, що й у matching — ADR-0004).

Наскрізний патерн: **portable-запит для коректності/тестів + БД-нативна структура для масштабу** (LIKE↔pg_trgm,
Python-cosine↔pgvector) — див. [ADR-0010](0010-portable-query-native-scale.md).

## Альтернативи

- *Пошук усередині catalog/matching* — змішує різні профілі навантаження і цикли деплою; окремий сервіс чистіший.
- *Одразу PostgreSQL FTS (`tsvector`)* — не портабельно на SQLite-тести; `LIKE`+`pg_trgm` дає робочу лексику
  зараз, FTS-ранжування — свідомий follow-up.
- *Тільки семантика* — гірша за точні коди/артикули; тримаємо обидва режими + гібрид (RRF) як follow-up.

## Наслідки

- Індекс — окрема проєкція; консистентність eventual (через події), що прийнятно для пошуку.
- Семантика над товарами постачальників корисна вже зараз; канонічний семантичний шар додасться з
  `catalog.product.updated`.
- Реальна embedding-модель — зміна залежностей за протоколом, не архітектури.
