# ADR-0007: Pricing Engine — ефективна ціна в UAH за умовами акаунта

**Статус:** прийнято · 2026-07-12

## Контекст

Один товар продається під різними акаунтами того самого чи різних постачальників, з різними умовами
(валюта розрахунку, знижка, платформна націнка). Ранжування «найдешевший» за сирим `price_uah`, який
надіслав постачальник, **ігнорує ці умови** — тож найдешевша пропозиція могла бути хибною. Потрібна одна
порівнянна величина.

## Рішення

Чистий доменний двигун (`offer/domain/pricing.py`, без I/O):

```
effective_price_uah = base → UAH × (1 − discount) × (1 + markup)
base → UAH:  UAH-акаунт → напряму;  інакше → fx_rate акаунта;  інакше → supplier price_uah (фолбек)
```

- Умови акаунта (`discount_pct`, `markup_pct`, `fx_rate_to_uah`) живуть у `supplier_account` (offer-сервіс).
  Вони **чутливі** (hard rule 6): ставляться через scope-gated admin-ендпоінт, ніколи не логуються і не
  віддаються read-ендпоінтами; агентам доступне лише похідне `effective_price_uah`.
- Обчислюється на upsert офера і **переobчислюється** при зміні умов акаунта; `None`, коли non-UAH офер
  не має придатного курсу (не можна оцінити в UAH).
- Зміна ефективної ціни публікується як подія `offer.effective-price.changed` (через outbox) → price-history
  веде тренд ефективної ціни (не лише сирої).

## Альтернативи

- *Рахувати ефективну ціну на льоту в кожному запиті* — не можна індексувати/ранжувати ефективно; матеріалізуємо.
- *Тримати умови в окремому account-сервісі* — передчасне дроблення; offer вже володіє `SupplierAccount` (§5.5).
- *Зовнішній FX-фід* — поза скоупом; курс — конфігурована умова акаунта, фолбек на supplier `price_uah`.
- *Віддавати сирі умови в API* — порушує hard rule 6; віддаємо лише похідну ціну.

## Наслідки

- «Best offer» і сортування тепер за `effective_price_uah` (індексований), а не за сирим `price_uah`.
- price-history отримує другий вимір (ефективна ціна) — окрема серія, щоб не колідувати з сирою.
- Зміна умов акаунта — потенційно масовий re-price його оферів; наразі синхронно в межах транзакції,
  за потреби виноситься у фонову задачу.
