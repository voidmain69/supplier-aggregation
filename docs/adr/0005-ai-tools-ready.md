# ADR-0005: AI-Tools-Ready — контракти на кожному сервісі + єдиний MCP Gateway

**Статус:** прийнято · 2026-07-11

## Контекст

Вимога: всі сервіси мають бути готові до використання AI-інструментами. Споживачі-агенти будуть питати ціни,
наявність, історію, каталог у розрізі категорій, шукати по артикулу/коду/абстрактному запиту.

## Рішення

Два рівні:

1. **Кожен сервіс AI-ready за контрактом** (не окремий "AI-шар"):
   OpenAPI 3.1 з LLM-якісними описами, `tool_manifest.json` (when-to-use/when-not-to-use/safety/cost),
   RFC 9457 помилки з підказками до дії, самодостатні відповіді, курсорна пагінація, `Retry-After`.
   Це enforced: spectral rules + `tools/check_conventions.py` у CI. Будь-який агент, що вміє OpenAPI,
   може працювати з сервісом напряму (всередині периметра).
2. **Єдиний MCP Gateway** назовні: курований набір інструментів (search, offers, history, catalog browse),
   а не 1:1 проксі всіх endpoint'ів — агенту потрібні task-oriented tools, не CRUD. Авторизація тими ж
   скоупами, що й REST; трейсинг кожного tool-виклику.

## Обґрунтування

- Описи в OpenAPI = описи для LLM — одна точка правди, не розсинхронізується.
- Курований шар MCP захищає від anti-pattern «агенту дали 200 ендпоінтів»: менше інструментів з чіткими
  when-to-use → вища якість агентних викликів.
- tool_manifest на сервісі дозволяє mcp-gateway (і майбутнім внутрішнім агентам) збирати інструменти автоматично.

## Наслідки

- Вартість: дисципліна описів у кожному PR (лінт частково перевіряє: наявність, довжина description).
- MCP Gateway — окремий сервіс, його tools версіонуються і мають власні contract-тести
  (golden-запити: «типові питання агента → очікувані виклики»).
