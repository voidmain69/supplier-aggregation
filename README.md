# Supplier Aggregation Platform

**Єдина точка правди про товари, ціни та наявність у багатьох постачальників — для людей, внутрішніх
сервісів і AI-агентів.**

Платформа підключається до API постачальників (перший — [Brain](brain_api_documentation.md)), забирає їхні
каталоги, ціни й залишки, зводить однакові товари різних постачальників в один **канонічний товар**, веде
**історію цін** і віддає все це через зрозумілі REST API та **MCP-шлюз для AI-інструментів**.

---

## Навіщо це потрібно

Коли товари закуповуються в багатьох постачальників, виникають типові болі, які ця платформа знімає:

- **«Один і той самий товар — у кожного постачальника свій».** У постачальника A це `productID 100463720`,
  у B — свій артикул, назва інша, характеристики оформлені по-різному. Платформа зводить їх у **один
  канонічний товар** за EAN/UPC (автоматично) та за схожістю характеристик через RAG (з підтвердженням
  оператором). Далі всі питають «наш товар», а не «товар постачальника X».
- **«У постачальника кілька акаунтів з різними умовами».** Один постачальник може мати кілька облікових
  записів з різними цінами, знижками, валютою розрахунку й термінами постачання. Платформа тримає **окрему
  пропозицію (offer) на кожен акаунт** і рахує ефективну ціну з урахуванням умов акаунта — видно, де і на яких
  умовах товар реально дешевший.
- **«Яка була ціна тиждень тому?»** Кожна зміна ціни фіксується — є повна **історія цін** з денними
  агрегатами (мін/макс/середня), трендами й точкою «найдешевше за весь час».
- **«Хочу, щоб AI-агент сам знайшов і порівняв».** Кожен сервіс віддає машиночитний контракт, а зовні є
  **MCP-шлюз** з готовими інструментами — агент може шукати, порівнювати ціни й наявність, дивитись історію
  без жодної інтеграції під капотом.

## Що платформа дозволяє робити

| Хочу… | Як |
|---|---|
| Знайти товар за артикулом / кодом / EAN | точний пошук у search-service |
| Знайти товар за абстрактним описом («материнка під Ryzen 9000 з Wi-Fi 7») | семантичний (RAG) пошук |
| Подивитись каталог постачальника в розрізі категорій | browse категорій |
| Отримати всі ціни й наявність по товару від усіх постачальників і акаунтів | offer-service, сортування за ефективною ціною |
| Знайти найкращу пропозицію з умовою «доставка ≤ 2 дні, потрібно 5 шт» | offer-service з фільтрами |
| Побачити історію ціни й тренд | price-history-service |
| Дати AI-агенту робити все вище через інструменти | mcp-gateway |
| Керувати зіставленням товарів вручну (курація) | matching-service + Curation UI |

## Для кого

- **Внутрішні сервіси компанії** (ERP, e-commerce, прайсинг) — через REST API за API-ключем і скоупами.
- **AI-агенти** (Claude та інші) — через MCP-шлюз з курованим набором інструментів.
- **Оператори-куратори** — через backoffice UI підтверджують зіставлення товарів.
- **Аналітика / BI** — через read-репліку БД.

## Як це працює (у двох словах)

```
Постачальники (Brain, …)                                Споживачі
        │  pull: каталог, ціни, залишки                  ▲
        ▼                                                │ REST / MCP
  Конектори ──події──▶ Каталог ─▶ Матчинг (EAN/UPC/RAG   │
  (rate-limited)      │           + курація оператором)  │
        │             ├─▶ Офери (мультиакаунт, ефективна ціна)
        │             ├─▶ Історія цін (time-series)
        └─▶ S3 (raw)  └─▶ Пошук (лексичний + семантичний) ─▶ API / MCP Gateway
```

- **Ingestion — event-driven**: конектори тягнуть дані з постачальників (з урахуванням лімітів, напр. Brain —
  3 запити/с на акаунт), публікують події про зміни. Читання — синхронний REST з передбачуваною латентністю.
- **Матчинг** безпечний: точні збіги за GTIN зводяться автоматично, решта — тільки після підтвердження людиною
  (помилкове злиття двох різних товарів дорожче за пропущений збіг).
- **Все AI-ready за контрактом**: OpenAPI 3.1 з описами під LLM + `tool_manifest.json` на кожному сервісі,
  зверху — єдиний MCP-шлюз.

Технічно: **монорепо** (Python 3.12, uv), **мікросервіси**, **event-driven** (Kafka/Redpanda),
PostgreSQL + TimescaleDB + pgvector. Чому саме так — у [ADR](docs/adr/).

## Сервіси

| Сервіс | Відповідальність |
|---|---|
| `connector-brain` (+ шаблон `connector-*`) | Ізолює специфіку постачальника: сесії, rate limit, нормалізація, raw→S3 |
| `sync-orchestrator` | Розклади й координація синхронізацій (повна / дельта / ціни) |
| `catalog` | Товари постачальників + канонічні товари + категорії |
| `matching` | Зіставлення EAN/UPC/RAG + черга курації оператора |
| `offer` | Мультиакаунтні пропозиції, фінансові умови, ефективна ціна |
| `price-history` | Історія цін (Timescale), агрегати, тренди |
| `search` | Гібридний пошук: лексичний (артикул/код) + семантичний (RAG) |
| `api-gateway` | Єдиний вхід для сервісів: auth, скоупи, rate limiting |
| `mcp-gateway` | MCP-інструменти для AI-агентів |

## Швидкий старт (після появи коду сервісів)

```bash
make up                      # локальний стек: Postgres(+Timescale+pgvector), Redpanda, Redis, MinIO, Grafana
make scaffold name=<service> # створити новий сервіс із шаблону
make lint test check         # перевірки перед пушем
```
